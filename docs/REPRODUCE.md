# Reproducing the EQUATES pilot cross-validation results

This document covers the headline pilot results: the 4-fold blocked-CV benchmark on the 12 km
EQUATES pilot (July 2019, central California, 72x72 cells). It gives the commands, the data and
split assumptions, the files you should get, how to check them, and how to read the
uncertainty. The pilot is one month of one emissions-free EQUATES run, so treat the results as
a pilot, not as a general claim.

## What is reproduced

| Output | Written by | Checked against |
|---|---|---|
| `results/benchmark_cv/main.md`, `main.tex` | `make_tables.py --cv` | regenerated byte-identical from the committed `results/results.csv` and `runs/` |
| `results/benchmark_cv/lead_rmse.md`, `.tex` | `make_tables.py --cv` | regenerated byte-identical |
| `results/benchmark_cv/figures/` | `make_tables.py --cv` | committed copies |
| `data/pilot_checks/cv_summary.md`, `cv_rmse_by_fold.png` | `summarize_equates_cv.py` | committed copies |
| per-fold paired differences | `fold_paired_check.py` | printed to stdout |

## Inputs

1. **Source data.** EPA EQUATES v1 CMAQ concentrations and CMAS meteorology, read from public S3
   buckets (no credentials). `configs/data/equates_2019_07_ca12km.yaml` names the exact files.
   `DATA_CARD.md` has the provenance and the known gaps (no emissions stream in this pilot).

2. **Extracted pilot files.** 63 files in `$AEROCAST_EQUATES_DIR/pilot/files`:
   31 daily concentration files, 31 daily meteorology files, and `static.nc`. Rebuild them with

   ```bash
   uv run python scripts/extract_equates_pilot.py --config configs/data/equates_2019_07_ca12km.yaml
   ```

   The script checks that a byte-range subset read matches a full-field read before writing.

3. **Results table.** `results/results.csv` (61 MB) holds every row the tables use. It is a
   plain Git file, not LFS, unlike `results/results_pilot.csv`.

4. **Run directories.** `runs/<run_id>/` (about 11 GB, git-ignored) holds `run.json`,
   `daily_stats.csv` and the other per-run outputs. `make_tables.py --cv` reads
   `daily_stats.csv` from each run, so these directories must be present. Each Slurm scope writes
   its own outputs to scratch and archives them to `$AEROCAST_PROJECT_ROOT/results/<scope>/`.
   Copy the CV run directories into `runs/` before you regenerate the tables.

## Data and split assumptions

- **Days.** 31 July 2019 days, hourly, surface layer. Each window is 6 input hours and 10 target
  hours, and the output is Ox (NO2 + O3) in ppbV.
- **Folds.** Four blocked-CV folds, each holding out one week as `test`, with a 5-day `val`
  block and 1-day buffers. The day blocks are in `configs/data/README_cv_folds.md` and in
  `configs/data/equates_2019_07_ca12km_fold{1..4}.yaml`. The test weeks are Jul 1-7, Jul 9-15,
  Jul 17-23 and Jul 24-30. They are disjoint, so the four folds pool into 28 out-of-fold test
  days.
- **Training budget.** The same for every model: up to 150 epochs with patience 20, a parameter
  budget of 4-6 M checked before each run, and 8 random-search trials in Ox mode (learning rate
  and weight decay drawn log-uniform, trial *i* using the same draw for every model). Selection
  uses the lowest validation Ox RMSE, saved to `results/benchmark_selection_<config>.json`.
- **Final runs.** The selected config, for each target mode (Ox, species, multitask), with seeds
  42, 43 and 44. Each seed's four fold runs pool into one out-of-fold test set.
- **High-Ox threshold.** The 95th percentile of Ox on training days. CSI(p95) and the RMSE above
  the threshold are computed against it.
- **Baselines.** Persistence and diurnal climatology, scored on the same test days.

## Commands

Run everything from the repository root on a GPU node. Pass your Slurm account at submission:

```bash
uv sync

# 1. Benchmark: 7 models x 4 folds (tuning, selection, then final runs), 28 tasks
sbatch -A <account> scripts/benchmark_array.sbatch
# ConvLSTM is the slowest model, so it runs as its own array of 4 tasks
sbatch -A <account> scripts/benchmark_array_convlstm.sbatch

# 2. Tables (uses only test rows; smoke-test rows are refused)
uv run python scripts/make_tables.py --cv --dataset equates_pilot --out results/benchmark_cv \
    --profile results/profile_equates.csv --reference gnn

# 3. Per-fold summary and the CSI figure
uv run python scripts/summarize_equates_cv.py

# 4. Per-fold paired differences against the same reference
uv run python scripts/fold_paired_check.py --reference gnn
```

Timings in `results/profile_equates.csv` come from `scripts/profile_equates.sbatch`. The CMAQ
wall-clock column is entered by hand.

## Verifying a regeneration

Regenerate into a scratch directory and compare with the committed copy:

```bash
uv run python scripts/make_tables.py --cv --dataset equates_pilot --out "$TMPDIR/regen" \
    --profile results/profile_equates.csv --reference gnn --no-previews
diff results/benchmark_cv/main.md "$TMPDIR/regen/main.md" && echo "main.md identical"
diff results/benchmark_cv/lead_rmse.md "$TMPDIR/regen/lead_rmse.md" && echo "lead_rmse.md identical"
```

Both should print "identical". The bootstrap uses a fixed seed (`--seed 0`), so the output is
deterministic given the same `results.csv` and run directories. A diff means the inputs differ,
not that the bootstrap is random.

The committed tables cover 7 models (UPT is not in them yet). Each has 3 target modes x 3 seeds
x 4 folds = 36 final runs, so 252 final run ids in total. Count them to check the inputs:

```bash
grep "benchmark_equates_fold[0-9]-final-" results/results.csv | cut -d, -f1 | sort -u | wc -l   # 252
```

Model-level results from an individual run can be checked with its `summary.txt` and
`per_window_rmse.csv` in its run directory.

## How to read the uncertainty

These measures answer different questions. Quote the one that matches the claim.

1. **95% CI in `main.md` and `lead_rmse.md`.** A block bootstrap over the 28 pooled test days
   (1000 resamples, seed 0). Each resample applies to the seed-mean metric. It captures
   sampling of test days only. It does **not** include training-seed variation, which is averaged
   out before resampling, and it does not separately model week-level variation.

2. **Paired ΔRMSE in `main.md`.** The difference from the reference model uses the same resampled
   days for both models. It is paired only if both were scored on identical test days.
   `make_tables.py` checks this and leaves the difference blank otherwise. The reference is set
   by `--reference` (default U-Net, the command above uses GNN).

3. **Mean ± std in `cv_summary.md`.** The spread across runs (seeds and folds together), not a
   confidence interval. Use it to judge how much a single run can move, not as a CI on the
   average.

4. **Per-fold paired differences from `fold_paired_check.py`.** One difference per fold (seed
   mean, same test week for both models), with a t-interval on the four differences (3 degrees of
   freedom). This is the check to use for claims about a difference between two models.

**Why measure 4 as well as 1.** Test days within a week are autocorrelated, so resampling single
days understates week-level variation. For U-Net minus GNN the day bootstrap gives
[+0.25, +0.51] while the t-interval over the four folds gives [-0.21, +0.90]. The fold-level
interval includes zero, so the day bootstrap is too narrow for that claim. Read a model
difference as established only if its fold-level interval excludes zero.

## Known gaps

- Only July 2019 is covered: four weeks of one run, one month of one emissions-free episode.
- The CI does not include training-seed variance (see 1 above).
- `results/results.csv` is not in LFS (61 MB). Track it with LFS before the file grows further.
- The run directories are git-ignored, so the regeneration above needs a copy from storage.
- The August 2019 extraction (`configs/data/equates_2019_08_ca12km.yaml`) is for the
  abnormal-weather test. It is not part of the CV results here.
- The committed tables predate UPT. Its rows appear once its benchmark array has finished and
  the tables are regenerated.
- Phase 2 runs are not final, so the model ranking in these tables is provisional.
